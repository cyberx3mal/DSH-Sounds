# Project sounds — звуковые уведомления по проектам для DeepSeek Harness

Русский | [English](README.en.md)

Репозиторий: [github.com/cyberx3mal/DSH-Sounds](https://github.com/cyberx3mal/DSH-Sounds)

Плагин для Web-интерфейса DeepSeek Harness (DSH): играет короткий синтезированный звук, когда:

- **завершилась работа** (turn закончился успешно);
- **нужно ваше решение** — запрос разрешения (approval), вопрос или план на утверждение;
- **сбой** — ошибка агента, исчерпанная квота, близкий к лимиту контекст, заблокированная цель, упавшая фоновая задача, падение сабагента, turn, завершившийся ошибкой или упёршийся в лимит токенов.

Каждый проект (рабочая папка / Workspace) может переопределить **любой из трёх звуков** или использовать общий. Если звук могли не услышать, включается **автоповтор до открытия проекта** — или заданное число повторов с выбранным интервалом.

## Что нового в 1.1.0

- Звук различает причину завершения turn: «Стоп» больше не звучит как «Работа завершена», а ошибка/лимит токенов дают «Сирена».
- Упавшие фоновые задачи (`ctx.jobs`) дают звук ошибки.
- Настройки хранятся в профиле DSH (общие для всех браузеров) с откатом на `localStorage`.
- Автоповтор до открытия проекта или N раз с интервалом.
- Режим «только когда вкладка в фоне», иконка в настройках, `aria-label` у переключателей.
- Ложные «Сирены» после перезагрузки страницы (уже заблокированная цель или заполненный контекст) убраны.
- Тесты, GitHub Actions и удаление оверрайдов удалённых проектов.

## Требования

- DSH с поддержкой bundle-плагинов (`dsh.bundle.patch`, `dsh.profile.bundles`) — проверено на Desktop `0.2.2-rc.2`.
- Хостовой половине нужен пакет `@deepseek-ai/schemastery` (объявлен в `dependencies`; при установке через `dsh plugin` подтянется автоматически).
- Системных зависимостей нет: звук синтезируется через Web Audio в браузере.

## Установка

### 1. Через npm

```sh
npm publish --access public
```

У получателя (профиль `desktop` у DSH Desktop, `web` у `dsh web` — подставьте свой):

```sh
dsh plugin --profile desktop add dsh-plugin-project-sounds
```

### 2. С GitHub

```sh
dsh plugin --profile desktop add github:cyberx3mal/DSH-Sounds

# зафиксировать версию (рекомендуется):
dsh plugin --profile desktop add github:cyberx3mal/DSH-Sounds#v1.1.0
```

### 3. Локальной папкой (для проверки или передачи архивом)

```sh
dsh plugin --profile desktop add file:C:/путь/к/dsh-plugin-project-sounds
```

Локальная установка создаёт ссылку (`link:`), поэтому зависимости не ставятся автоматически — выполните в папке плагина:

```sh
npm install
```

Без этого хостовая половина не сможет импортировать `@deepseek-ai/schemastery`; клиентские звуки при этом продолжат работать, а настройки останутся в браузере.

> Не перемещайте и не удаляйте папку после установки — плагин перестанет загружаться. Для «насовсем» распакуйте архив в постоянное место.

### 4. Вручную без CLI

1. Распакуйте папку пакета.
2. Скопируйте её в `%USERPROFILE%\.dsh\profiles\<профиль>\node_modules\dsh-plugin-project-sounds`.
3. В `%USERPROFILE%\.dsh\profiles\<профиль>\package.json` добавьте:
   - в `dependencies`: `"dsh-plugin-project-sounds": "1.1.0"`;
   - в `dsh.profile.bundles`: `"dsh-plugin-project-sounds"`.
4. Выполните `npm install` в папке плагина и перезапустите DSH.

После обновления хостовой половины (версия плагина, `index.js`) нужен перезапуск DSH; клиентские правки подхватываются обновлением страницы (`Ctrl+R`).

## Использование

1. Откройте **Настройки** (шестерёнка внизу слева).
2. Выберите раздел **«Звуки проектов»** — теперь у него есть иконка.
3. Что внутри:
   - **Включить звуковые уведомления** — общий выключатель;
   - **Громкость** — 0–100%;
   - **Только когда вкладка в фоне** — не играть, пока окно DSH активно;
   - **Общие звуки** — три звука по умолчанию: «Работа завершена» → **Перезвон**, «Нужно разрешение или ответ» → **Дерево**, «Ошибка» → **Сирена**; рядом «Прослушать»;
   - **Автоповтор** — повторять сигнал, если его могли не услышать:
     - **Когда остановиться**: «Когда проект открыт» или «После заданного числа повторов»;
     - **Интервал**: 5–300 секунд;
     - **Число повторов**: 1–30 (для режима с числом повторов).
   - **Звуки по проектам** — для каждого проекта три выпадающих списка: «Готово», «Внимание», «Ошибка». Значение **«Общий»** наследует звук из блока выше (подпись показывает, какой именно); выбранный звук сразу проигрывается;
   - **Вернуть значения по умолчанию**.
4. После первого клика/нажатия клавиши браузер разблокирует Web Audio — дальше звуки играют сами.

### Как считается «прочитано»

- Автоповтор проекта замолкает, когда проект **открыт в основной области** (любая его сессия видна на экране), либо когда ожидающий approval/question закрыт. Если проект уже был открыт в момент сигнала, звук играет один раз — повтор не нужен.
- Сигналы без проекта (квота, истёкший вход) замолкают, когда вкладка снова видна или вы кликнули в окне.
- В режиме «до открытия проекта» повтор всё равно прекращается через 10 минут, чтобы не звенеть бесконечно.

### Где хранятся настройки

Настройки живут в **профиле DSH** (Host settings document) и общие для всех браузеров, подключённых к этому профилю. При первом запуске поля, которые профиль ещё не переопределял, берутся из браузера и один раз записываются в профиль; явно сохранённые в профиле значения главнее. Пока Host-настройки недоступны или профиль только для чтения, используется `localStorage` этого браузера. Внизу страницы настроек написано, какой режим действует.

## Как это работает

- Клиентская половина (`client.js`) подписывается только на публичные поверхности DSH:
  `api-session/status` (старт/финиш turn), `api-session/error`, `deepseek-account/*`,
  `ctx.uiSession.sessionStatus` (ожидающие approval/question/plan-review),
  проекции `goal`, `contextPressure` и `lastTurnEnd` из `ctx.sessions.list`,
  ростер фоновых задач `ctx.jobs`, цепочку `shell.quota-notice`,
  и `retainedBy.mainView` у строк сессий (открытый проект = прочитано).
- Хостовая половина (`index.js`) регистрирует проекцию `lastTurnEnd` (причины `turn/end`:
  `completed`, `aborted`, `blocked`, `error`, `max-tokens`, `interrupted`, `forked`)
  и объявляет volatile `Config` со всеми настройками, чтобы клиент читал и писал их через `ctx.configForms`.
- Звуки — 12 встроенных пресетов, синтезируются на месте (осцилляторы + огибающая), файлов нет.
- Под-агенты не дают звук «завершено» (чтобы не шуметь), но их ошибки дают звук ошибки.
- «Стоп» пользователем даёт `aborted` и не звучит; ошибка и лимит токенов дают «Сирению».

## Ограничения

- Работает только в Web-интерфейсе (DSH Desktop и `dsh web`); при полностью закрытом окне звука не будет — для этого нужен host-плагин с системным звуком.
- Фоновые задачи отслеживаются для сессий, которые работают сейчас или работали последние 5 минут (не более 24 сессий одновременно); падение задачи, случившееся намного позже, звук не даст.
- «Прочитано» — это открытый проект, а не открытые настройки: переход в настройки автоповтор не останавливает.
- Настройки Host-профиля общие между браузерами, поэтому громкость и автоповтор тоже общие (в отличие от старого localStorage-режима).
- Если профиль недоступен для записи, настройки остаются локальными для браузера.

## Разработка

```sh
npm install
npm test          # node --test: host + client, включая миграцию и автоповтор
npm run check     # node --check index.js && node --check client.js
```

Код — обычный ESM + браузерный `window.__ModuleLoader__.load`, сборка не нужна. Тесты поднимают реальный `client.js` с заглушками `window`, `localStorage`, Web Audio и сервисов DSH, поэтому проверяют поведение, а не копию логики. CI — `.github/workflows/ci.yml`.
